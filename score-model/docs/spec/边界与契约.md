## 1. 踏板

| kind | MS 语义 | 当前实现 | 建议 |
|---|---|---|---|
| `sustain` | 制音器抬起（延音） | ✅ 完整（MIDI CC64 + 合成；**半踏板 depth 已生效**） | 优先使用 |
| `sostenuto` | 只保持触发时刻的音 | ✅ 完整（MIDI CC66 + 合成按 targets） | 可用 |
| `una_corda` | 弱音 / 音色变化 | ✅ 合成变暗（depth 目前按开关处理） | 可用 |
| `sordino` | 弱音器装上/取下（弓弦、铜管、簧片） | ✅ 合成变暗、收得短 | 可用 |
| `tuning`（竖琴） | 改音级 ♭/♮/♯ | ⚠ 只写 MIDI CC，合成未建模 | 少用；用了进 `pedal_skipped` |
| `swell`（管风琴） | 表情/音量 | ⚠ 只有增益，无音色联动 | 可用，别指望"开大风箱变亮" |
| `hihat`（鼓组） | 踩镲开合 | ⚠ 仅 CC4，合成未建模 | 少用 |

## 1b. 演奏动作（用 `turns` 表达，不是踏板 kind）

| 动作 | 现在怎么写 | 实现 |
|---|---|---|
| 换弓 / 上弓 / 下弓 | `turn=bow_change` / `bow_up` / `bow_down`（仅弓弦） | ✅ 音头摩擦/轻重不同 |
| 拨奏 ↔ 拉奏 | `turn=pizz` / `arco`（仅弓弦） | ✅ 拨奏改用拨弦衰减 |
| 泛音 | `turn=harmonic`（弓弦/拨弦） | ✅ 高八度、更纯 |
| 换槌 / 软槌 / 硬槌 | `turn=mallet` / `mallet_soft` / `mallet_hard`（击体） | ✅ 亮暗不同 |
| 吸气 | `turn=inhale`（管乐/人声） | ✅ 音前气声 |
| 琴键机械声 | `turn=key_noise`（击弦） | ✅ 极短瞬态 |
| 弱音器装上/取下 | `turn=mute_on` / `mute_off` | ✅ 声音变暗 |
| 滑音/滑指 | `curves` 的 `pitch_cents` 两点 | ✅ 音内弯音 |
| 弓位（靠指板/靠桥） | `curves` 的 `bow_position` | ✅ 暗/亮 |
| 颤音深度 | `curves` 的 `vibrato` | ✅ 深度可调（频率取该乐器 timbre） |

仍**做不到**（MS 里没有对应结构，别硬凑）：

| 动作 | 为什么 | 备注 |
|---|---|---|
| wah / 移调踏板 | 连续扫频，属演奏过程曲线 | 可用 `brightness` / `pitch_cents` 近似 |
| 双音/和弦的**分别**弓位 | 弓位是整件乐器的连续参数 | 同一乐器同一时刻只能一个值 |
| 逐音颤音的**独立包络** | `vibrato` 是乐器级曲线 | 同刻多音共用一条 |
| 连音线 / 圆滑线 | 记谱层结构，MS 不存 | 谱面画不出 tie |
| 拍速变化（rubato） | MS 无速度轨 | 见 `数学乐谱规范.md` |

## 3. 写作时的取舍顺序

1. **优先**：能用 `sustain`/`sostenuto`/`una_corda`/`sordino` 表达的，就用这几种。
2. 其次是 `turns`（逐音动作）与 `curves`（连续参数）。
3. 拿不准的（如 `tuning`）先不用，或写进 `gaps` 说明。

## 4. 完整清单：现在做不到的（2026-10-24 核对）

### 4a. 格式/模型里**没有结构**（要先想清楚要不要）

> 2026-10-24 按管理者意见收敛：左右手各自踏板/音色（物理上不存在，一台琴一个踏板）、
> 采样音源选择（不属 MS）、效果器（不属乐谱）、wah/whammy 扫频（属效果）**不再列为缺口**。
> 同批已补：记谱对照（`记谱对照.md`）、踏板 `tuning`/`hihat`/`swell` 合成、鼓件映射、
> 弓长/逐音微差、MIDI 动作导出、capo。

| # | 项 | 为什么 | 现在能怎么绕 |
|---|---|---|---|
| 1 | 谱面**版面**细节（跨行连线、符尾斜度、装饰音记号回显） | 动作与符号已能对照（`记谱对照.md`），缺的是排版美化 | 不影响语义，属排版层 |
| 2 | 速度**语义**（tempo 轨/渐快渐慢的记号） | MS 是绝对时间，直接排 onset 即可；MIDI 也可给 tempo_map | 时间上照写；谱面不显示速度术语 |
| 3 | 逐音音准微调（±音分，非整件乐器） | `pitch_cents` 是乐器级曲线；竖琴已能按音级调（`tuning` 踏板） | 整段偏移用曲线；单音准要靠调音踏板 |

**"音内变化"不需要新结构**：把长音**拆成两个（或几个）事件**，在变化点挂 `turns`（换弓/再击/…）
并各给力度，就能做出音内的转折、渐强、重新起音——这正是现有格式的用法。

### 4f. S02 阶段二（P0–P7）的边界

| # | 项 | 现状 / 边界 |
|---|---|---|
| 1 | 变体识别 | 只认**完全**倒影/逆行/节奏变形；移调体现在"同动机多次出现"里，不单独升级为变体；变体扫描只扫母动机所在旋律线 |

| 6 | 校准 | 段级阈值随分段算法变化（改 `split_ratio` 要重跑）；长曲在分布里权重更大 |
| 7 | 前端 | JSON 视图 / SVG 分析图 / 补丁协议都有；**没有 GUI 编辑器**，也没有前端页面（只有 API 与 SVG） |
| 8 | 补丁 | 只做 dry-run + MS 行级提示，**不自动写 `.ms`**；`voice`/`staff` 等 S02 专有字段无 MS 对应 |
| 9 | 增量索引 | 按**旋律线**增量（动机/变体复用）；特征与段落仍整体重算 |
| 10 | 性能 | 7.4k 音：索引 2.4s、报告 0.5s、SVG 0.4s；~20k 音预估 15s 量级（变体扫描最贵） |

## 0. 术语（对齐）

| 词 | 指什么 | 例子 |
|---|---|---|
| **模型** | **引擎的数据模型**（结构定义） | SPEC §7 的事件 / 踏板轨 / 约束档 |
| **文件** | **按模型结构写出的数据** | `.ms` / `.s02.json` |
| **引擎** | 读模型 + 呈现 + 编辑的**程序** | 渲染器 / 编辑器 / 排版引擎 |

**关键**：模型不是独立于引擎的抽象物——**它就是引擎的模型**；文件是模型的序列化形式。三者对应关系固定：改模型 → 文件结构与引擎行为一起变。

---

## 1. 定位：它是"编辑器"，不只是"查看器"

```
读取 MS ──┬─→ 呈现：视觉（事件图形谱 / 可选五线样式）
          ├─→ 听觉：按 calibration 算出声音参数 → 交音频后端
          └─→ 编辑：产生模型层修改 → 校验 → 写回
```

**关键前提**：编辑**必须**经过模型 API 与校验，**不得直接改文件**。
理由：编辑＝产生事实。若绕过校验，模型会被非法数据污染（如 release<onset、音高越界、同键同刻重叠），而这些正是 §7.7 要拦的。

## 3. 六条铁律

| # | 铁律 | 若不遵守会发生什么 |
|---|---|---|
| **E1** | 写入必须经模型 API，不得直接改 `.ms` | 文件里出现未校验数据，等于模型外有"影子事实" |
| **E2** | 每次提交前跑 §7.7 不变量 + 约束档；失败**拒绝并指出违反哪条** | 非法状态被接受，后续比较全污染 |
| **E3** | 编辑**不得伪造来源**：手工补的值不得标成 `measured` / `midi_inverted` | "人填的"被当成"测出来的"，证据链断裂 |
| **E4** | **id 稳定**：修改不换 id；删除**不复用** id | 引用（tie 组、踏板 targets、派生依赖）断链或错指 |
| **E5** | 不得仅为显示方便改结构（继承边界 B2） | 例：把连续踏板深度降为开关 |
| **E6** | 撤销/重做必须存在，且**撤销后的状态也要通过校验** | 出现"撤销到非法态"，或撤销绕过不变量 |

## 6. 排版引擎：要做，分阶段交付

**排版引擎属引擎的呈现子系统，本阶段在范围内。** 呈现样式**不限于五线谱**：

| 样式 | 说明 | 阶段 |
|---|---|---|
| 事件图形谱 | 时间轴 + 键盘 + 力度 + 踏板轨 | **阶段 1** |
| 五线谱（简化） | 单声部、基本符头/符干、踏板标记 | **阶段 1** |
| 五线谱（规范） | 多声部、连音弧、符尾分组、跨行 | 阶段 2 |
| 数字简谱 | 1234567 记法 + 高低八度点 | 阶段 2 |
| 其他样式 | 引擎按自身规则扩展 | 视需要 |

**阶段 1 的判据**：**人能读懂**（音高、时间先后、力度差异、踏板状态可辨认），而不是"符合印刷规范"。
**阶段 2 的判据**：可用于实际写作与交付（排版规则、多声部、跨行、样式切换）。

> 我之前把"完整五线排版引擎"写进"不做清单"，是把**分阶段**说成了**不做**——已更正：**排版引擎要做**，只是规范级排版排在阶段 2。

### 明确不做的（真不做，范围外）

- **音频合成/混响**：引擎只出参数，不产声音文件
- **协作、版本合并**
- **编辑时自动修正非法值**（如把越界音高吸附到最近键）——那是静默改事实

| 输出模型版本 | ScoreV02（现有表示，不重构） | D-3 |
| 支持范围版本 | ScopeVersion（契约 §11 结构，判定开始时冻结） | D-4 |

- **B-1**：禁止无方向声明执行转换。
- **B-2**：禁止将 `S02→MS` 结果表述为"无损"或无限定"往返"；唯一合法术语=**范围内往返等价**（契约 §6）。

## 2. 输入契约（转换器接受什么）

| 输入 | 要求 | 核对 ID |
|---|---|---|
| 源对象 | 数学乐谱字段对象（ScoreFields/语义核可校验形态） | I-1 |
| 输入验证 | **先过语义核 `ms_semantics.validate` / `ms_fields.validate_fields`**；失败→转换拒绝（J3=rejected），不得跳过 | I-2 |
| 五态与 F/I/D | 状态、值、错误通道三分不合并；basis/reference 随字段 | I-3 |
| ScopeVersion | 判定开始前已冻结（契约 §11 约束一） | I-4 |
| 派生依赖 | 若走 §4.1 方式 B：许可+依赖+规则版本必须齐 | I-5 |

- **B-3**：禁止绕过验证器（不得内联复制规则冒充校验；语义核须被业务路径真调用）。
- **B-4**：禁止接受无 ScopeVersion 的转换请求（判定链 §9.4 步 1 无法成立）。

**I-2 说明（裁决补充）**：**源对象验证通过 ≠ 源对象全部语义均可转换。** 字段模型验证证明的是源对象符合当前验证器约束，**不构成**目标 ScoreV02 表达能力或无损性的证据。源对象验证与转换支持范围判定是**两个独立步骤**：验证通过只允许进入后续转换流程；某字段/语义是否被目标表示支持、是否落入 ScopeVersion，须在映射阶段（C2）逐项判定并留证。禁止由"验证通过"推出"支持范围完整"或"可无损转换"。

## 3. 输出契约（转换器必须产出什么）

### 3.1 目标对象

| 输出 | 要求 | 核对 ID |
|---|---|---|
| 目标对象 | ScoreV02 表示（角色不变：事实表示） | O-1 |
| 输出验证 | 目标对象过**自身验证器**；失败=转换失败 | O-2 |
| 保留项对照表 | 契约 §2 逐项映射结果（见 O-3 细则） | O-3 |
| 损失清单 | 丢了什么、为何丢、影响哪层语义（有损失时必附） | O-4 |
| 判定输出 | 契约 §9.6 结构（exec / J1 / J2 / policy_basis / losses / hard_violations / omitted_derived） | O-5 |

**O-3/O-4 细则（裁决补充）——映射记录不得被三分法抹掉核验状态：**

- 映射结果可归类为**保留 / 损失 / 合法省略**，但这是**映射结果分类**，不是"必须三选一填表"。
- **每项必须记录实际核验状态与证据**（已核对保留 / 已确认损失+原因 / 合法省略+许可依据 / **未解决**）。
- **合法省略标记的门槛**：仅当满足冻结契约 §4.1 条件（许可+依赖+规则版本）才可标为合法省略（K-4）；不得因"表要填满"把未处理项塞进合法省略。
- **未解决项必须保留其未解决事实**（无法核验 / 无法映射 / 关系未解析），并进入判定路径（§9.4 步 3、步 6）——**不得**为制造 L'=∅ 从损失清单中移除未解决项。
- O-4 损失清单与"未解决项清单"职责不同：前者=已确认的语义损失；后者=尚未得出结论的待处理事实。两者都不得静默消失。

- **B-6**：禁止把"未确认"归入 J3 任一值；无执行结果 ≠ completed。

1. **必须识别并记录**：未知 / 不支持 / 未解析跨片段关系不得静默丢弃、不得猜测归属（跨片段关系须记：关系类型+涉及对象+缺失机制）。
2. **是否可有损、是否必须失败**，由冻结 ScopeVersion、KEEP_POLICY 与判定链整体决定——**不是**"一律失败"，也**不是**"记下即可丢"。

4. 引用悬空（指向不存在对象）→ 报告，不伪造目标。

**B-21 细则（裁决补充）——缺失声明项的后果按所属阶段判定，不得粗暴统一：**

| 缺失发生阶段 | 后果 | 对应 J3/判定 |
|---|---|---|
| **执行前**缺方向/模型版本声明 | 不能开始转换，入口前置条件拒绝 | J3=rejected |
| **判定前**缺冻结 ScopeVersion | 无法完成合法判定 | 判定不成立，J2=禁止交付（B-4） |
| **转换完成后**输出缺版本声明 | 输出不满足交付契约 | 不得宣称"转换通过"；按 §9 判定交付许可 |

- **禁止**用统一的失败标志掩盖"前置条件失败 / 执行错误 / 输出契约不满足"之间的区别（对应 J3 三分与"未确认"边界）。

## 6. KEEP_POLICY 处理边界（契约 §9.3 + §11.4）

**总原则（裁决）：KEEP_POLICY 是判定输入，不是最终判定结果。** 政策类别不得直接映射为 J2=允许交付；最终交付许可由判定链（ScopeVersion 许可 + 硬性义务优先 + 其他失败条件）推出。

| 政策 | 含义 | 损失发生时的判定路径（不得由实现改判） | 核对 ID |
|---|---|---|---|
| HARD_NO_LOSS | 硬性保留，损失即违约 | J1=转换失败，J2=禁止交付 | K-1 |
| HARD_DEGRADEABLE | **潜在**可降级的硬性保留——不是无条件交付许可 | ① 先查冻结 ScopeVersion：该项是否具有**有效降级许可** ② 许可有效+前置条件完整+无更高优先级失败条件 → 才可 J1=有损转换、J2=允许交付（清单必附） ③ 缺许可/依据不完整/触发硬性义务 → 按契约判定，**不得由实现自行放行** | K-2 |
| LOSSY_OK | 允许有损（范围外/扩展） | J1=有损转换；J2 **仍受整个判定链与其他硬性约束制约**——不是绕过检查的捷径；清单必附 | K-3 |
| OMITTABLE_DERIVED | 合法省略派生 | 不计入语义损失——**仅当**许可+依赖+规则版本齐（§4.1 方式 B）；否则回落损失 | K-4 |

- 默认政策以契约 §11.4 表为准（F/I·VALUE/ABSENT/UNDETERMINED=HARD_NO_LOSS；F/I·UNSUPPORTED=HARD_DEGRADEABLE 默认但受边界一约束；D 类按 §4.1）。
- **H-3 细则**：未核验项不得默认为无损；"没有发现损失" ≠ "已经证明无损"。
- **K-2/K-3 细则**：硬性义务优先于降级许可；任何政策类别都不得绕过 §9.4 判定链的 H_fail 检查与 J2 独立判断。

## 7. 判定链实现边界（C3 预告，本阶段只定边界）

判定必须可追踪地走完契约 §9.4 的 9 步；实现不得：

- 跳过步 1（前提）或步 6（L' 计算）
- 合并 J1/J2 为一个标志（B-7）
- 在步 7 用"最轻损失"而非"最严重损失主导"
- 缺失 policy_basis 仍输出结论

每步产出必须进入 O-5 结构；**判定顺序与依据可追踪**是 C3 关闭条件。

## 3. 三类转换结果（转换成功 ≠ 语义等价）

| 结果 | 含义 | 硬要求 |
|---|---|---|
| **完整等价** | 约定范围内的信息与语义均保留 | 范围必须写明（"约定范围"四字不可省） |
| **有损转换** | 存在明确记录的信息损失或无法映射项 | **损失清单必附**（丢了什么、为何丢、影响哪层语义） |
| **转换失败** | 无法满足转换契约 | **拒绝或显式失败**，不得输出半成品冒充成功 |

状态命名可在实现时细化，但**三类语义不可合并**。附加纪律：禁止把"有损转换"报成"完整等价"；禁止把"转换失败"降级成"有损转换"继续交付。

### 3.1 结果分类与交付许可分离（裁决收紧）

**"发生了信息损失"与"是否允许交付"是两个独立判断**，不得因为都有损失就给出同一交付结论：

| 情形 | 结果判定 | 交付许可 |
|---|---|---|
| 违反**硬性保留要求**（事实/来源/五态被丢） | 不得判"完整等价" | **是否允许有损交付取决于该要求是否允许降级——不允许则必须失败** |
| **允许有损处理**的信息（范围外扩展等） | 有损转换 | 允许交付，**必须附损失清单** |
| **合法省略**可重算派生结果 | 不视为语义损失 | 仅当契约明确允许 + 重算条件完整 + 规则版本可识别（详见 §4.1） |

**任何情况下都不得静默改变信息含义。** 本节不增加第四类结果——只是把结果分类与交付许可分开判定。

## 4. 允许丢失的信息与报告方式

| 类 | 允许丢失？ | 报告方式 |
|---|---|---|
| 原始记谱事实 | **否**（丢失=违反硬性保留；按 §3.1 判定失败或降级） | 丢失清单 + 原因 + 是否允许降级 |
| F/I/D 来源 | 否 | 同上 |
| 五态 | 否（无法映射=硬性保留受损；按 §3.1） | 同上 |
| 派生结果 | 可省略（合法省略，见 §4.1） | DERIVABLE_PENDING + 规则版本 + 依赖 |
| 流式对象/创作意图 | 本就不在数学乐谱层 | 无需转换（职责边界） |
| 语义核之外的扩展 | 视支持范围（允许有损类） | 损失清单 + 范围版本 |

### 4.1 派生结果的两种可接受转换方式（裁决收紧）

**能重算 ≠ 已证明能正确重算**——保存了依赖不等于结果语义等价（规则版本丢失时，新规则生成的结果不能自证等价）。

| 方式 | 要求 |
|---|---|
| **A. 保留派生结果** | ① 保留语义身份 ② 保留结果值 ③ 保留**足以识别计算依据**的信息（规则版本） |
| **B. 转为待重算** | ① 省略必须获支持范围与转换规则**明确许可** ② 记 DERIVABLE_PENDING ③ 保留必要依赖与规则版本 ④ 明确"尚未完成重算"，**不得冒充已计算结果** ⑤ 重算完成后**必须验证结果符合约定的等价标准** |

**禁止**：派生结果丢失后生成的新结果直接宣称与旧结果等价。

## 5. 转换后的验证标准

1. **输入验证**：源对象先过自身验证器（语义核/validate），失败则转换拒绝
2. **输出验证**：目标对象过自身验证器；失败=转换失败
3. **保留项对照**：§2 逐项核对（事实/来源/五态/派生/缺口）
4. **结果判定**：按 §3 三类出结论 + 损失清单（若有）
5. **语义核真调用**：转换代码必须调用验证器，不得内联复制规则（防绕过）

## 6. 往返声明规则（仅在明确范围内）

- **不预设双向无损**。固定术语为**「范围内往返等价」**——不得未加限定地简称"无损往返"（后者易被误解为整个模型无损失）。
- 只在满足全部条件时声明"范围内往返等价"：
  1. 正向与反向的支持范围均有版本化声明
  2. 反向转换的输入包含正向输出的全部保留项
  3. 往返测试在**声明范围内**逐项对照通过（见下比较基准与维度）
  4. 范围外信息的丢失已有显式清单

### 6.1 比较基准与维度（裁决收紧）

**基准 = 转换前的源对象**（不是转换后的结果反向定义标准）。在声明范围内按**字段语义 + 预先声明的规范化规则**逐项比较；仅契约明确允许的表示差异可忽略。**不得**以序列化字节一致或音符数量/主要字段相等代替语义比较；转换可能改变内部组织形式而保留语义，也可能表面结构相似却丢失来源/缺省状态/记谱含义。

| 维度 | 比较要求 |
|---|---|
| 原始记谱事实 | 声明范围内语义等价 |
| F/I/D 来源属性 | 来源不丢失、不混淆 |
| 五态状态 | 语义保持，不得静默降级 |
| 派生结果 | 按声明规则与版本验证，或明确处于待重算状态（§4.1） |
| 允许的表示差异 | **必须预先声明规范化规则，不得事后放宽** |

- 声明模板：「在范围 vN 内，数学乐谱→ScoreV02→数学乐谱 满足【事实/来源/五态/派生】四项**范围内往返等价**（基准=源对象）；范围外信息见损失清单」——**缺任一项不得简称"无损往返"**。

### §6.2 最低往返覆盖（MIN_COVERAGE）

**6.2.1 定义与硬前提**：`MIN_COVERAGE` 是**契约级**最低往返覆盖清单，由本契约维护。任何 `S02→MS` 的 ScopeVersion 必须同时满足 `includes ⊇ MIN_COVERAGE` 且 `includes ≠ ∅`，否则 R6 验收不成立。**实现者不得增删本清单以规避失败**；清单变更属契约变更（见 6.2.6）。

**6.2.2 三类验收对象（不得混为同一验收对象）**：

- **基础事实（F）**：以**转换前源对象**为基准，按 §6.1 逐字段比较语义；
- **派生结果（D）**：默认方式 A（保留可比较结果 + 规则版本）；**当该派生结果在目标模型中无存储、只能现算时，采用方式 B**——须同时满足：明确省略许可、`DERIVABLE_PENDING` 标记、保留依赖、保留规则版本、**重算后按预先声明的比较标准验证等价**。**"能重算"不等于"往返保真"**；
- **结构对象（S）**：非字段对象，按 6.2.4 逐类声明。

**6.2.3 清单（F 5 / D 2 / I 3 / S 4）**：

| 类 | 项 | 比较/处理 |
|---|---|---|
| F | `onset_us`、`release_us`、`pitch_spelling`、`pitch_semitone`、`tuplet_ratio` | 源事件逐项比较（半音见 6.2.10；时间容差见 6.2.9） |
| D | `simultaneous_set`（`sim-v1`）、`sustained_spans`（`susp-v1`） | **方式 B**：重算 + 规则版本 + 后验等价 |
| I | `performed_duration`、`tempo_curve`、`micro_offset` | **声明制**：默认不覆盖；声明包含则须单独提供往返证据 |
| S | tie 组、踏板、声部/谱表归属（**奏法/装饰属记谱层，不在此列**，见 6.2.4 S2） | 按 6.2.4 |

**6.2.4 结构对象四要素**（每类必须声明，**仅写类别名称无效**；S2 于 C-004 后改为记谱层声明）

- **S1 tie 组**：保留＝连接关系 + 成员身份 + **记谱顺序**；识别＝`TieGroup.member_ids` 引用真实 id，音高一致性由 `validate()` 以**半音**校验；比较＝成员 id 序列 + 声部 + 组数，组边界不得合并/拆分；**拼写保真另按 `pitch_spelling` 逐成员比较**（同半音异拼写不得声称拼写一致）；失败＝悬空引用→不可判定、组缺失→损失清单、顺序改变→语义改变。
- **S2 奏法/装饰（记谱层，C-004 后）**：**不参与 `MS` 侧往返比较**。理由：MS 记演奏事实（实际时长/力度），记谱记号在写谱层由 `articulation-v1` / `ornament-v1` 换算成结果，**记号本身不入 MS**；谱面→MS 会丢失"这是 staccato/装饰音"这一记号信息，须**进损失清单**。若 `S02` 侧自身保留记号，则只在 `S02↔S02` 比较，且必须声明其归属层。
- **S3 踏板**：保留＝**`composed` 与 `interpreted` 两层各自独立、不得合并** + `action_notated` 记号语义 + `target_scope`；比较＝类型/记号动作/时点 + 来源标签；失败＝来源混为模糊标签→违约、时点缺失→不可判定；**"执行轨迹"层当前未建模，若要求其参与覆盖属未登记缺口**。
- **S4 声部/谱表归属**：保留＝逐事件 voice/staff；比较＝逐事件相等（整体重编号须预先声明规范化规则）；失败＝归属丢失＝事实丢失。

**6.2.5 范围冻结与排除**：范围版本在判定开始前冻结（§11 约束一）。排除**仅限 §4 表所列允许丢失类**；其余排除一律无效。排除项必须**逐项进入损失清单**，不得以 `excludes` 记录代替损失清单。

**6.2.6 清单变更机制**：`MIN_COVERAGE` 变更属**契约变更**，须附 change_log（增/删/语义变更逐项）与影响面；**不得由单次转换的 ScopeVersion 变更**；清单版本与 ScopeVersion 版本分别记录、可机械比较。

**6.2.7 R6 通过条件（全部满足才成立）**：①反向范围非空 ②`includes ⊇ MIN_COVERAGE` ③范围与规范化规则验收前冻结 ④等价标准预先声明 ⑤必要正向表示正确 ⑥反向恢复满足语义等价 ⑦排除项进入损失清单 ⑧未决项保持可追踪、不得默认转通过。

**6.2.8 附加否决条件**：若正向目标表示本身不正确，**即使反向结果与源对象碰巧一致**，也不得仅凭最终比较通过认定整条转换链正确。

**6.2.9 时间基准与量化**：`MS→S02` 投影必须声明并冻结 `time_base`（每四分音符多少微秒）、网格分辨率（`ticks_per_quarter`）与舍入规则。时间维度比较允许 **≤0.5 tick** 的量化偏差；**容差不得事后放宽**。量化属**预先声明的表示差异**（§6.1），不是信息损失；残差须可复算。`time_base` 是**投影参数**，不是 MS 的事实内容。

**6.2.10 规范化规则（半音）**：`pitch_semitone` 的比较基准为**由 `pitch_spelling` 按声明规则重算后的值**；不得声称"半音被独立存储/独立保留"。半音相同不得替代拼写相同。

**6.2.11 往返比较维度（MS 事件模型）**：除 §6.1 四维外，另比——①`onset_us`/`release_us`（整数相等，容差见 6.2.9）②`release_state`（三态一致；`sustaining` 与 `NOT_PROVIDED` **不得互认**）③`dynamics_permille` + `dynamics_scale` + `calibration_ref`（任一不同即不等；**`NOT_PROVIDED` 与 `1000` 不等**）④踏板段序列（种类/`start`/`end`/`depth`/`scope`；`mechanical` 下另比派生保持集合与 `sost-hold-v1` 版本）⑤派生键号与 `piano_id` ⑥`excitation_type`。**不得以"声音听起来一样"替代上述比较。**



## 9. 三类结果的机器判据（C-①）

> 目标：让系统能**依据契约判定**转换结果，而不是靠实现自觉。结果分类、交付许可、实际执行结果是**相关但不同的三个判断**——机器判据把它们联系起来，但**不得合并成一个模糊的成功标记**。

### 9.1 判定输入（转换执行必须产出）

| 输入 | 内容 |
|---|---|
| 执行事实 | completed / rejected / error（执行层结果，不是判定结论） |
| 保留项对照表 | §2 逐项：保留 / 损失 / 合法省略（每项带原因与政策引用） |
| 损失清单 | 丢了什么、为何丢、影响哪层语义 |
| 支持范围声明 | 本次转换声明的范围版本内包含哪些项 |

### 9.2 三个独立判断

| 判 | 名称 | 取值 |
|---|---|---|
| **J1** | 结果分类 | 完整等价 / 有损转换 / 转换失败 |
| **J2** | 交付许可 | 允许交付 / 禁止交付 |
| **J3** | 执行结果 | completed / rejected / error（**封闭枚举**） |

J3 是事实，不是结论；J1 与 J2 由损失与政策推出，**各自独立成立**（§3.1）。J3=completed **不能**直接推导 J1/J2——执行正常仍须按保留情况与政策判定（例：执行成功但丢失不可降级事实 → J3=completed，J1=转换失败，J2=禁止交付——不矛盾，三判各答各的问题）。

**J3 封闭枚举与语义**（裁决补充）：

| J3 | 含义 | J1/J2 约束 |
|---|---|---|
| completed | 转换执行正常结束 | **仍须**按实际保留情况与政策判定 |
| rejected | 因契约或输入校验不满足被拒绝 | J1=转换失败，J2=禁止交付 |
| error | 执行期间出错，未完成有效转换 | J1=转换失败，J2=禁止交付 |

**「未确认」是外部判定状态**（非 J3 枚举值）：执行状态无法确认时（无输出/结果丢失/超时未归因）→ **判定未完成，禁止交付**；不得凭空归入 J3 任一状态。**执行事实缺失不得被误判为正常完成**——"没有拿到执行结果"≠ completed。未确认不是第四种业务结果分类，也不是正常执行结果。

### 9.3 每项保留要求的政策（KEEP_POLICY）

| 政策 | 含义 | 损失后果 |
|---|---|---|
| **HARD_NO_LOSS**（不可降级） | 硬性保留，损失即违约 | J1=转换失败，J2=禁止交付 |
| **HARD_DEGRADEABLE**（可降级） | 硬性保留，但契约允许有损交付——**可降级性必须来自预先声明的契约许可（范围版本），不得由转换实现自行决定** | J1=有损转换，J2=允许交付（损失清单必附） |
| **LOSSY_OK**（允许有损） | 范围外/扩展信息 | J1=有损转换，J2=允许交付（清单必附） |
| **OMITTABLE_DERIVED**（合法省略） | 派生结果按 §4.1 方式 B | **不计入语义损失**（条件：许可+依赖+规则版本） |

默认政策建议（待 C-② 范围版本定稿确认）：原始记谱事实=HARD_NO_LOSS；F/I/D 来源=HARD_NO_LOSS；五态=按状态细分（ABSENT/UNDETERMINED 丢失倾向 HARD_NO_LOSS——伪造信息存在性；UNSUPPORTED 丢失=HARD_DEGRADEABLE——须报告缺口转移；NOT_PROVIDED/DERIVABLE_PENDING 参照 OMITTABLE_DERIVED）；派生=OMITTABLE_DERIVED；扩展=LOSSY_OK。

### 9.4 判定程序（冻结判定链，9 步）

**前置条件（裁决补充，必须先过）**：判定所需的输入、范围声明、政策归属与**保存核验**均已完成。若存在无法核验的必检项，**不得视为无损**——按预先定义的失败或未完成处理规则处置，且**禁止交付**。

> **"没有发现损失" ≠ "已经证明无损"**：某源字段未被检查、目标字段未确认保留、证据缺失导致损失未入清单——都会造成空损失清单的**假完整等价**。未核验项不得计入 L=∅。

```
1. 检查契约前提：方向、模型版本、范围版本、输入有效性、必检项核验均已确认
2. 确定 J3：不得根据输出是否存在臆测执行是否完成（含"未确认"处理）
3. 逐项应用 KEEP_POLICY：记录保存情况、损失类别、许可依据、policy_basis
4. 计算 H_fail：HARD_NO_LOSS 被违反 → J1=失败、J2=禁交付
5. 处理合法派生省略：仅当许可+依赖+规则版本齐全时从语义损失中排除
6. 计算 L'：未核验项不得默认为无损
7. 确定 J1：失败优先 > 有损 > 完整等价（最严重损失主导）
8. 独立确定 J2：按契约许可，不得被单一 success 标志覆盖
9. 输出 policy_basis：每项结论可回溯到政策、保存义务、核验结果、损失处理
```

| 判定分支 | 结果 |
|---|---|
| J3 ∈ {rejected, error, 未确认} | J1=转换失败；J2=禁止交付 |
| H_fail ≠ ∅ | J1=转换失败；J2=禁止交付 |
| L' ≠ ∅（扣除合法省略后） | J1=有损转换；J2=允许交付（附损失清单） |
| L' = ∅ **且保存核验证据充分** | J1=完整等价；J2=允许交付 |

**关键**：每个结论必须由证据与预先声明的规则推出，**不能由实现自行解释或降级**。

### 9.5 防降级纪律（机器强制）

| 禁止 | 机制 |
|---|---|
| 失败降级为有损 | J1=失败只能由 HARD_NO_LOSS 损失或 J3 失败触发；实现无权改判 |
| 有损误报为等价 | L' ≠ ∅ 时 J1 不得为完整等价（由判定程序保证） |
| 合法省略冒充保留 | OMITTABLE_DERIVED 须满足 §4.1 条件（许可+依赖+规则版本），否则回落为损失项 |
| 交付绕过 J2 | J1 与 J2 分别输出；**禁止**用单一"成功"标志覆盖两者 |

### 9.6 判定输出（机器可读结构）

```
{
  "exec": "completed | rejected | error",
  "J1_result": "FULL_EQUIVALENT | LOSSY | FAILED",
  "J2_delivery": "DELIVER | REJECT",
  "policy_basis": [每项损失的政策引用与判定理由],
  "losses": [损失清单],
  "hard_violations": [HARD_NO_LOSS 违反清单],
  "omitted_derived": [合法省略清单（含规则版本与依赖）]
}
```

输出必须能回答："为什么是这个结论"（policy_basis 逐项可追溯）。

## 12. G8 接口边界（C-③）

> 边界：只定义片段转换需要的**契约信息、范围与引用边界声明、未解析关系的报告方式**；**不实现跨片段机制、不启动 G8 工程任务、不改 ScoreV02、不做转换实现**。

### 12.1 片段转换需要的契约信息

| 信息 | 要求 |

### 12.2 未解析跨片段关系的报告方式

转换遇到**跨片段关系**（tie 跨片段、tuplet 跨片段、Pattern/Variant 跨片段引用）而机制未建时：

## 11. 范围版本格式（C-②）

> 边界：只定义范围版本的**契约对象与格式**；不实现转换器、不改 ScoreV02、不重构 G1–G8、不提前定义 G8 接口。

### 11.1 范围版本必须回答的四项

| 项 | 必须回答的问题 |
|---|---|
| **范围包含项** | 本次转换承诺处理哪些字段、语义和对象？ |
| **政策归属** | 每项保存义务适用哪一种 KEEP_POLICY？ |
| **变化可识别性** | 范围、政策或规则变化时，如何识别版本差异？ |
| **五态默认政策** | 各字段状态默认适用什么政策？哪些情况必须显式声明？ |

### 11.2 范围版本对象（契约结构）

```
ScopeVersion = {
  version: "SV-n",
  direction: "MS→S02" | "S02→MS",        # 转换方向（§1）
  includes: [ {item, semantic_id, keep_policy, notes} ],
  excludes: [ {item, reason} ],
  normalization_rules: [...],              # §6.1 预先声明的允许表示差异
  change_log: [...]                        # 相对上一版本的逐项变化
}
```

**约束一（裁决）**：**范围版本先于转换判定确定**——判定开始时冻结；实现不得在发现损失后临时修改范围或政策（否则防降级失效）。

### 11.3 变化可识别性与结构校验

- 版本号变化**必须附 change_log**：新增项 / 删除项 / 政策变更 / 规范化规则变更，逐项列出
- 两个版本须可机械比较：includes 差集 + keep_policy 映射差异 + normalization_rules 差异
- **只改版本号、无 change_log = 无效版本**（无法判断改了什么）
- **change_log 不能代替机械比较**：日志说明"变了什么"，机械比较验证"实际变化与声明一致"——两者**相互核验**，不得只信日志文字
- **结构校验规则**：
  1. `includes` 与 `excludes` 不得对同一语义对象产生未解决冲突（冲突=版本无效）
  2. `normalization_rules` 的变化**必须纳入机械比较**（它影响等价判定，不是普通备注）
  3. 政策由严格变宽松时，change_log 必须识别其**对保存义务与交付许可的影响**（不是普通版本升级）
- 比较结果喂给 §6.1 的"预先声明"要求——事后放宽规范化规则 = 版本违规
- 所有变化必须在**判定开始前生效**（约束一冻结点）

### 11.4 五态默认政策（约束二：默认政策不得掩盖状态语义）

| 字段类 × 状态 | 默认 KEEP_POLICY | 必须显式声明的情况 |
|---|---|---|
| F/I · VALUE | HARD_NO_LOSS | 允许降级时 |
| F/I · ABSENT | **HARD_NO_LOSS**（丢失=伪造信息存在性） | 任何降级 |
| F/I · UNDETERMINED | **HARD_NO_LOSS**（丢失=伪造确定性） | 任何降级 |
| F/I · UNSUPPORTED | HARD_DEGRADEABLE（默认值，见边界一） | 转为其他政策时 |
| F/I · NOT_PROVIDED | **不自动获得省略许可**（见边界二） | 按字段输入要求与范围契约显式定 |
| D · VALUE | OMITTABLE_DERIVED（方式 A 优先；B 条件见 §4.1） | 省略时 |
| D · DERIVABLE_PENDING | OMITTABLE_DERIVED（**须满足 §4.1 方式 B 条件**） | 不省略而硬性保留时 |

**边界一（裁决）：UNSUPPORTED 的默认政策不得覆盖硬性保存义务。** UNSUPPORTED 只说明当前模型/实现无法表达或处理某项信息，**不自动说明该信息可以丢失**。实际允许降级必须由**冻结的范围版本及其交付许可**决定；若与其他硬性保存义务冲突，**硬性义务优先**。例：范围内必保留的原始事实无法表达 → 不得因 UNSUPPORTED 降级为可交付的有损结果（该失败就失败）。

**边界二（裁决）：NOT_PROVIDED / DERIVABLE_PENDING 不得获得无条件省略许可。** 二者语义不同——NOT_PROVIDED=输入未提供；DERIVABLE_PENDING=具备计算条件但尚未计算。

- DERIVABLE_PENDING 的合法省略**必须满足 C-① 已冻结条件**：明确许可 + 完整依赖 + 规则版本 + 重算后验证等价
- NOT_PROVIDED 能否省略，由**字段的输入要求与范围契约**决定；若该项是本次转换的**必需输入**，NOT_PROVIDED 不得当合法省略
- **OMITTABLE_DERIVED 仅适用于满足其定义条件的派生结果**——不是所有缺失/未计算状态的通用豁免；**状态的默认政策不能取代字段适用性、依赖条件与交付许可检查**（与 ms_semantics 状态语义一致：缺失/待计算/合法空结果/计算失败不得互相冒充）

**约束二细则**：ABSENT 与 UNDETERMINED 的区别**必须保护**——丢失二者区分所需信息 = 改变事实语义 = 违约。同一项在不同方向政策不同时，**每个方向分别显式声明**。

### 11.5 与 C-① 判定链的连接

- §9.4 第 1 步的"范围版本"= 本节 ScopeVersion；第 3 步政策归属来自 `includes[].keep_policy`
- 冻结点 = 判定开始时刻（约束一）
- C-③（G8 接口）只需引用 ScopeVersion 的字段标识与政策，不提前实现跨片段机制
