# 写作手册（合并版）

> 由 写作入口 / MD文档格式 / 作曲流程 / 旧档案线格式 合并；

## 1. 写作入口

> **口径**：MS 是**数学模型**（不是文件格式）；落到磁盘上只有两种文件尾标识——
> **`.md`（文档写法）** 与 **`.py`（脚本写法）**，脚本的产物同样落 `.md`。
> 其他任何后缀、任何结构、任何别人给的模板，都**不是入口**。
>
> 本页是「怎么写」的唯一真相源；`.md` 的内部结构见 [`MD文档格式.md`](MD文档格式.md)。

---

## 1 两种写法

| | **方式一：写 `.md` 文档** | **方式二：写 `.py` 脚本** |
|---|---|---|
| 适合 | 新曲、改编、改几个音、调力度、改配器 | 算法生成、批量处理、循环铺织体、参数遍历 |
| 你写什么 | 一份 Markdown，按拍写音符 | 一段 Python，调 `ms.Writer` / `ms.start` |
| 产物 | 直接就是 `.md` | 脚本跑完落 `.md` |
| 谁来读 | 人、AI、程序都能读 | 只有程序能跑 |
| 改动成本 | 低（改一行就是一个音） | 中（改一行要重跑） |

**判据一句话**：能一次想清楚每个音的 → 写 md；需要算的 → 写 py。
两者可以混用：脚本铺底稿导出 md，人再手改。

---

## 2 方式一：写 `.md`

### 2.1 最小可运行样例

```markdown
# 水镜

- BPM: 63
- Meter: 4/4

## 乐器

- 1: acoustic_grand_piano

## 乐谱

```notes
[n1] 1: C4 @0+1 mf
[n2] 1: E4 @1+1 mf
[n3] 1: G4 @2+2 f
```

## 动作

- pedal: 1 sustain 0 4
```

### 2.2 四步

1. **定头**：`# 曲名`、`- BPM:`、`- Meter:`。
2. **列乐器**：`- 序号: 类型码`。类型码写错会直接报错并列出候选——不要猜着写。
3. **写音符**：`[标签] 序号: 音高 @起拍+时值 力度`。
4. **写动作**：`- turn:` / `- pedal:` / `- curve:`，引用音符标签，不是行号。

### 2.3 写完必须校验

```powershell
cd score-model
python tools\mscli.py validate ..\inbox\<曲名>\<曲名>.md
```

红字报错就改，**不要跳过**。校验器只做确定性检查（音域、重叠、引用、时间），它说错就是真错。

### 2.4 能写什么，先问工具

```powershell
python tools\mscli.py ms catalog        # 有哪些乐器、类型码是什么
python tools\mscli.py ms menu           # 一句话菜单：能写什么 / 怎么查 / 怎么写
```

不查就写 = 幻觉的主要来源。工具给出的类型码是唯一权威。

## 3 方式二：写 `.py`

### 3.1 两种 API，按需要选

```python
# A. Writer：命令式，适合逐音控制
import ms

w = ms.Writer(bpm=63, meter=(4, 4))
p = w.instrument("acoustic_grand_piano")      # 同类型可再调一次 = 第二件
a = w.note(p, pitch="C4", beat=0, beats=1, level="mf")
w.note(p, pitch="E4", beat=1, beats=1, level="mf")
w.chord(p, pitches=["C4", "E4", "G4"], beat=4, beats=2, level="f")
w.pedal(p, "sustain", 0, 6)
w.turn(a[0], "retrigger", 900)                # a[0] 是事件；乐器做不了会直接报错
w.save("..\\inbox\\水镜\\水镜.md")             # 产物落 md
```

```python
# B. start/notes DSL：紧凑，适合批量铺
import ms

g = ms.start(bpm=96, instruments=[{"type": "piano"}])
g.notes(["C4@0+1/mf", "D4@1+1", "E4@2+2/f"])
song = g.finish()
song.save_md("..\\inbox\\草稿.md")
```

### 3.2 三条纪律

1. **先声明乐器再写音**：`instrument()` 返回实例号，后面所有音符都引用它。
2. **动作引用返回值**：`w.note()` 返回的就是稳定 id，别自己编。
3. **产物落 `.md`**：`save()` 不给后缀时自动补 `.md`；不要另造后缀。

## 5 禁止项（防幻觉）

| 禁止 | 后果 |
|---|---|
| 用别的后缀存 MS 模型 | 口径分裂；下次打开时你或 AI 会再猜一次 |
| 在 md 里发明字段或语法 | 未识别内容被静默忽略，你以为写了 |
| 凭记忆写乐器类型码 | 报错，或写成一个存在但不对的乐器 |
| 用行号当引用 | 增删一行，所有转折/踏板指向错音 |
| 不校验就交付 | 硬撞音、越界、重叠会一路带到成品 |
| 一次写 30 分钟的大曲 | 分乐章、分段落写，每段校验一次 |

## 2. MD文档格式

> **口径先分清三件事：**
>
> | 概念 | 是什么 | 有文件形态吗 |
> |---|---|---|
> | **MS 格式** | **MS 数学模型**：事件模型、语义、六条不变量（`数学乐谱规范.md` §7） | **没有**。它是内存里的 `MSDocument` |
> | **`.md`** | 模型的**文档写法** | 有，一份 Markdown |

>
> 所以：**「MS 格式」指的是模型，不是文件尾标识。** 文件尾标识只有 `.md` 与 `.py` 两种。
>
> 本页只定 `.md` 的内部结构；两种写法的分工与禁止项见 [`写作入口.md`](写作入口.md)。
>
> 任何文档、示例、提示词、脚本帮助文本，都不得再把落盘写成那个后缀。

## 0 一份格式，两种写法

`.md` 里可以有两种写法，`ms_md.loads()` 自动识别，调用方不需要区分：

| 写法 | 谁写 | 时间单位 | 字段 | 识别特征 |
|---|---|---|---|---|
| **标签式**（作者层） | AI / 人手写 | **拍**（按 BPM 换算） | 只写该写的：音高 / 起拍 / 时值 / 力度 | 含 ` ```notes ` 代码块 |
| **表格式**（无损档案） | 程序导出 | **µs**（忠于 MS） | 全字段，可无损往返 | 含 `## 音符` 表格 |

> **写作用标签式，存档用表格式。** 两者同名 `.md`，不要另造后缀。

---

## 1 标签式（写作默认）

### 1.1 完整示例

```markdown
# 水镜

- BPM: 63
- Meter: 4/4

## 乐器

- 1: acoustic_grand_piano
- 2: violin

## 乐谱

```notes
[n1] 1: C4 @0+1 mf
[n2] 1: G4 @1+2 mp
[n3] 2: C5 @0+4 p
```

## 动作

- turn: n2 retrigger 900
- pedal: 1 sustain 0 2
- curve: 2 dynamics 0 600 4 900
```

### 1.2 逐行语法

| 位置 | 写法 | 说明 |
|---|---|---|
| 第 1 行 | `# 曲名` | 标题，可省 |
| 头部 | `- BPM: 63` | 必填项之一；缺省 120 |
| 头部 | `- Meter: 4/4` | 缺省 4/4 |
| 乐器 | `- 1: violin` | 序号从 1 起；`P1:` / `p1:` 写法等价 |
| 音符 | `[标签] 序号: 音高 @起拍+时值 力度` | 力度可省（省 = `NOT_PROVIDED`，不猜） |
| 转折 | `- turn: 标签 类型 强度` | 强度缺省 1000；标签必须是已出现的音符标签 |
| 踏板 | `- pedal: 序号 类型 起拍 止拍` | 拍为单位；深度固定 1000（全踩） |
| 曲线 | `- curve: 序号 参数 拍 值 拍 值 …` | 成对的「拍, 值」；至少一对 |

**音高**：`C4` / `F#5` / `Bb3` / `C♯4`；八度必写。取值范围 MIDI 21–108，越界直接报错。

**标签**：`[A-Za-z_][\w]*`，自己起，只在本文件内有效。它**不是** MS 的 id——编译时按出现顺序映射成稳定 id（`L00000001`…），所以增删音符不会让后面的标签错位。

**时间**：全部以**拍**为单位，小数可用（`@2.5+0.5`）。编译时按 BPM 换算成 µs；BPM 变了，同一份 md 的绝对时间随之变，这是有意的——写谱时你只想得到「第几拍」。

### 1.3 力度等级（写谱层锚点）

| 写法 | 千分比 | 对应 MIDI 力度 |
|---|---|---|
| `ppp` | 250 | 16 |
| `pp` | 516 | 33 |
| `p` | 766 | 49 |
| `mp` | 1000 | 64 |
| `mf` | 1250 | 80 |
| `f` | 1500 | 96 |
| `ff` | 1750 | 112 |
| `fff` | 1984 | 127 |

> **`mp` = 1000 是零点**，不是 `mf`。等级表属写谱层，不进 MS 数值；换算只在编译时做一次。
> 不写力度 = `NOT_PROVIDED`，播放器按乐器默认处理——**不要用不写来偷懒**，该标的强弱要标。

### 1.4 标签式的已知边界

以下内容标签式**写不了**，需要时改用表格式或 `.py` 脚本：

- 人声段（`vocal`／声母-韵母-韵尾切分）、歌词绑定
- `grace`（倚音）、`off_kind`（止音方式）、`off_ramp_us`
- 逐音 `state` / `src` / `scale` / `calib` 等溯源字段
- 缺口（`gaps`）声明
- 多条曲线（实现按「最后一条生效」处理，一条以上请用表格式）

写不出来就换写法，**不要发明字段**——发明字段会被静默忽略，然后你以为写上了。

## 2 表格式（无损档案）

程序导出的完整形态，能无损往返 `MSDocument`。

```markdown
# MS 乐谱模型 · 水镜

---
ms: 1
channels: per_instance
piano_count: 1
constraint_mode: single_piano
trailing_silence_us: 0
bpm: -
meter: -
---

## 乐器
| id | type | subtype | section |
|---|---|---|---|
| P1 | acoustic_grand_piano | - | - |

## 音符
| id | inst | onset_us | release_us | pitch | permille | state | src | scale | calib | exc | grace | off | ramp |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| L00000001 | 1 | 0 | 500000 | C4 | 800 | VALUE | composed | relative_permille | manual | impulse | 0 | - | 0 |

## 踏板
| id | inst | kind | start_us | end_us | depth | scope | targets |
|---|---|---|---|---|---|---|---|
| D00000001 | 1 | sustain | 0 | 1000000 | 800 | mechanical | - |

## 转折
- event=L00000002 kind=retrigger strength=900

## 曲线
- inst=1 param=dynamics time_us=0 value=500 ramp=0

## 人声段
- event=L00000001 index=0 kind=initial text=ch tone=2 binding=B00001 turn=0 lang=zh onset_us=0 release_us=100000

## 缺口
- code=cc_not_imported severity=info detail=...
```

**约定**：

- 缺失值一律写 `-`，不写 `null` / 空 / `0`（`0` 是有意义的值）。
- 表头顺序固定，加载器按列名取值，不按位置。
- `bpm` / `meter` 属呈现参数，不属于 MS 数值；表格式里写 `-`，由使用方传入。
- 表格式是**机器产出**，人手改只应该改文档里明确允许改的字段，改坏了加载即报错——这是设计意图，不是 bug。

## 4 禁止项

| 禁止 | 为什么 |
|---|---|
| 用别的后缀存 MS 模型 | 后缀是写作口径的一部分；多一个后缀就多一次「该用哪个」的幻觉 |
| 在 md 里发明字段 | 未识别的字段被静默忽略，你以为写了其实没写 |
| 用行号 / 出现顺序当引用 | 增删一行就全错；用 `[标签]` |
| 标签式里写 µs | 标签式的时间单位是拍；要精确到 µs 请用表格式 |
| 把 `-` 改成 `0` | `0` 与「未提供」是两件事，改了就丢语义 |
| 手改表格式的 `id` 列 | id 是引用锚点；改了转折/人声段就指向别人 |

## 5 与 `.py` 脚本的关系

`.py` 是另一种写法，不是另一种格式：

```python
import ms
w = ms.Writer(bpm=63)
p = w.instrument("acoustic_grand_piano")
w.note(p, pitch="C4", beat=0, beats=1, level="mf")
w.pedal(p, "sustain", 0, 2)
w.save("piece.md")          # 产物同样是 .md
```

脚本的价值是**能算**（循环、序列、随机、批量改），md 的价值是**能读能改**（AI 直接写、人直接看）。
两者产物完全同构：脚本生成的 `.md` 可以被人接着改，人写的 `.md` 可以被脚本继续加工。

选择判据：

| 想干的事 | 写法 |
|---|---|
| 写一首新曲、改几个音、调力度 | `.md` |
| 生成 200 小节的练习曲、批量移调、按算法铺织体 | `.py` |
| 从 MIDI / MusicXML / ABC 转进来 | 导入器（产物 `.md`） |

## 3. 作曲流程

## 术语口径

| 词 | 含义 | 有文件形态吗 |
|---|---|---|
| **MS** | **MS 数学模型**：事件模型 + 语义 + 六条不变量（数据结构本身） | **没有** |
| **MD** | 模型的**文档写法**（标签式 / 表格式） | 有，`.md` |
| **PY** | 模型的**脚本写法**（`ms.Writer` / `ms.start` 直接构建） | 有，`.py`，产物落 `.md` |
| **S02** | 分析层的流式结构（测量 / 动机 / 分段） | 有，`.s02`（投影产物，可重算） |

> **说「MS 格式」时指的是模型，不是文件尾标识。**
> 写谱只写 `.md` 或 `.py`；谱面、音频、S02 都是**产物**，不是源。

## 文件标识与产物

| 标识 | 是什么 | 用途 |
|---|---|---|
| `.md` | **文档写法**：标签式（按拍写）或表格式（全字段无损） | 写谱、存档、交接 |
| `.py` | **脚本写法**：可循环可计算 | 算法生成、批量处理 |
| `.s02` | 分析层结构 | 结构测量，别手写 |
| `.mid` `.wav` `.png` `.svg` `.abc` | 呈现产物 | 交付/试听/看谱 |

> 旧档案（换格式前落盘的文件）读取器仍能载入，只读兼容；新作品一律 `.md`。

## 主流程

### A. 写 `.md`（推荐 AI / 手写）

```markdown
# 我的曲子
- BPM: 87
- Meter: 4/4

## 乐器
- 1: piano

## 乐谱
```notes
[n1] 1: C5 @0+1 mf
[n2] 1: E5 @1+1
```

## 动作
- turn: n2 retrigger
- pedal: 1 sustain 0 2
```

写完编译 / 规范化：

```python
import ms, ms_md
song = ms_md.compile_song(open("piece.md", encoding="utf-8").read())
song.save_md("piece.md")     # 规范化写回（仍是 .md）
song.export_png("piece.png", bars_per_page=4, width=2000)
```

### B. 写 `.py`（AI 写代码）

```python
import ms

g = ms.start(bpm=87, instruments=[{"type": "piano"}])
n1 = g.note(1, "C5", beat=0, beats=1, level="mf")   # 返回稳定 id
n2 = g.note(1, "E5", beat=1, beats=1)
g.turn(n2, "retrigger")
song = g.finish()
song.save_md("piece.md")     # 产物落 .md，没有第二种后缀
song.export_png("piece.png")
```

### C. 任务 JSON（兼容旧路径）

```python
song = ms.build(spec)          # spec 是结构化输入，不是写作格式
song.save_md("piece.md")
```

## 1. 总体结构

```
ms 1                              ← 魔数 + 格式版本
channels per_instance             ← per_instance（单乐器单通道）| per_section（同类乐器单通道）
piano_count 3
constraint_mode n_pianos
trailing_silence_us 250000        ← 可选：显式结尾留白

instruments 3                     ← 本曲使用的乐器实例；数量 = 行数
P1 acoustic_grand_piano steinway_d - -   ← 实例号 + 类型码 + 子类型 + 声部组 + 收束覆盖
P2 celesta - - -
P3 soprano - vocals -

dict step  C D E F G A B          ← 字符串走字典，行里写索引
dict rel   given sustaining NOT_PROVIDED
dict state VALUE NOT_PROVIDED ABSENT UNDETERMINED UNSUPPORTED DERIVABLE_PENDING
dict src   measured midi_inverted notated_inferred

## 2. 词法规则

| 规则 | 说明 |
|---|---|
| 分隔 | 空格 / 制表符；字段间可有多个空格 |
| 行 | 一行一条记录；`\n` 或 `\r\n` 均可 |
| 注释 | `#` 开头的行**整行忽略**（不做行尾注释，避免转义） |
| 空行 | 忽略 |
| 编码 | UTF-8（无 BOM） |
| 缺失值 | `-` |
| 数字 | 十进制整数，不带分隔符、不带前导 `+` |

## 3. 固定字段顺序

### 3.1 事件流 `events`（音符 16 列 / 踏板 7–8 列 / 发声段 11 列，按时间排）

事件流里有四类行，靠**列数**区分，按时间排序（同刻：踏板 → 音 → 该音的发声段 → 止音）：

| 行 | 列数 | 首列 | 含义 |
|---|---|---|---|
| 音符 | 15（旧 16） | `L`+8 位 | 表见下；**只写起始时间** |
| 踏板 | 7 或 8 | 数字或 `D`+8 位 | 见 §3.2 |
| 发声段 | 11 | `L`+8 位，第 2 列固定 `vocal` | 见 §3.3d |
| 止音 | 3–5 | `L`+8 位，第 2 列固定 `off` | 见 §3.3e |

音符行（15 列，定长；**没有释放时间列**——停止由止音事件给出）：

| # | 字段 | 类型 | 说明 |
|---|---|---|---|
| 1 | `id` | `L` + **8 位零填充** | 形如 `L00000001`；唯一、只增、不复用 |
| 2 | `piano_id` | int ≥1 | 琴号（必须是本曲声明的乐器 id） |
| 3 | `onset_us` | int | **起始**（微秒） |
| 4 | `semitone` | int 0..127 | 键号 |
| 5 | `permille` | int / `-` | 力度千分比；`NOT_PROVIDED` 时为 `-` |
| 6 | `grace` | `0`/`1` | 装饰音标志 |
| 7 | `rel` | 字典索引 | `given`（有止音事件）/`sustaining`（故意不收）/`NOT_PROVIDED` |
| 8 | `state` | 字典索引 | 力度五态 |
| 9 | `src` | 字典索引 / `-` | 来源（可空） |
| 10 | `exc` | 字典索引 | 激励类型 |
| 11 | `step` | 字典索引 | 音名 C..B |
| 12 | `alter` | int | -2..2 |
| 13 | `octave` | int | -1..9 |
| 14 | `scale` | 字典索引 | 力度标尺 |
| 15 | `cal` | 字典索引 / `-` | 标定引用（可空） |

> 旧文件里的 16 列音符行（第 4 列是释放时间）仍可读；**新写出一律 15 列 + 止音事件**。

**踏板 kind 六种**

| 索引 | kind | 语义 | 典型乐器 |
|---|---|---|---|
| 0 | `sustain` | 制音器抬起（延音） | 钢琴、钢片琴、颤音琴 |
| 1 | `sostenuto` | 只保持触发时刻的音 | 三角钢琴 |
| 2 | `una_corda` | 弱音 / 音色变化 | 三角钢琴 |
| 3 | `tuning` | 调音（depth 三档 0/500/1000 = ♭/♮/♯） | 竖琴（7 踏板，targets 指音级） |
| 4 | `swell` | 表情 / 音量 | 管风琴 |
| 5 | `hihat` | 踩镲开合 | 鼓组 |

> 电吉他/电贝斯的 wah、移调等属**连续演奏动作**，不是踏板状态，不进本表（见 `已知边界.md`）。

### 3.3e 止音事件（事件流里的 3–5 列行，第 2 列固定 `off`）

音符只写起始时间；**停止**是一条独立事件——因为不同乐器"怎么停"不一样，
而且**都有缓冲**，不是到点硬切。

```
L00000001 off 500000 - -
L00000002 off 620000 damper 70000
```

| # | 字段 | 说明 |
|---|---|---|
| 1 | `event_id` | 停哪个音（必须存在） |
| 2 | `off` | 固定标记 |
| 3 | `time_us` | 止音开始时刻（微秒） |
| 4 | `kind` | 止音方式，`-` = 按乐器机制取默认（见下表） |
| 5 | `ramp_us` | 缓冲长度，`-` = 按机制默认 |

**机制默认**（`core/ms_instruments.OFF_DEFAULTS`）：

| 机制 | kind | 缓冲 | 说明 |
|---|---|---|---|
| `hammered_string` 击弦/钢琴 | `damper` | 70ms | 制音器落下 |
| `bowed_string` 弓弦 | `bow_lift` | 45ms | 离弦（比制音快） |
| `plucked_string` 拨弦 | `pick_stop` | 60ms | 手/掌停弦 |
| `struck_body` 击体 | `mallet_damp` | 80ms | 手/毡止音 |
| `lip_reed` 唇簧（铜管） | `breath_stop` | 130ms | 收气（最慢） |
| `single_reed` 单簧 | `breath_stop` | 110ms | |
| `air_jet` 气簧（笛） | `breath_stop` | 100ms | |
| `vocal_fold` 人声 | `breath_stop` | 90ms | |
| `electronic` 电子 | `electronic_off` | 15ms | 断电式（最快） |
| `noise` 噪声 | `electronic_off` | 20ms | |

- 校验 V2：`kind` 必须在 `OFF_KINDS` 内；`ramp_us` 在 0..2s。
- 踏板是**另一件事**：延音踏板决定"按住期间是否继续响"，止音决定"松开这个音何时开始收"。
  两者叠加：踏板按住时，实际收尾在踏板抬起处按同一 ramp 衰减。

### 3.2 踏板行（8 列，可退化为 7 列）——写在 `events` 事件流里

踏板是**控制事件**，和音符一样带 id 与乐器，**和音符同处一条事件流、按时间排序**
（不再单独成块；旧文件的 `pedals` 区块仍可读，重写时会并入事件流）。

| # | 字段 | 类型 |
|---|---|---|
| 1 | `id` | `D`+8 位（可选；省略时整行为 7 列旧写法） |
| 2 | `piano_id` | int（哪台乐器） |
| 3 | `kind` | 字典索引（`kind` 表；0=`sustain`） |
| 4 | `start_us` | int（按下） |
| 5 | `end_us` | int / `-`（抬起；`-` = 未抬起） |
| 6 | `depth_permille` | int 0..1000 |
| 7 | `scope` | `mechanical` / `explicit` |
| 8 | `targets` | `-` 或逗号分隔的事件 id（仅 explicit 用） |

```
events 3
L00000001 1 0 500000 60 800 0 0 0 0 0 0 0 4 0 c
D00000001 1 0 500000 1200000 800 mechanical -     ← 0.5s 踩下，插在时间线上
L00000002 1 1000000 1500000 64 800 0 0 0 0 0 2 0 4 0 c
```

> **绑定规则**：踏板只作用于 `piano_id` 这台乐器，且该乐器必须在
> `instruments` 里**声明过**（V8b），`kind` 必须是该乐器声明的踏板（V14）；
> 覆盖哪个音按时间算——按下时仍在该乐器上发声的音，以及按下之后起的音，
> 直到抬起（换踩 50ms 内接续）。
> `targets` 写了具体 id 就只作用于这些音，写 `global` 等同缺省。
> 不带 `id` 的 7 列旧行照旧可读可写（字节不变），不会被强加 id。

### 3.2b `instruments` 行（5 列）

| # | 字段 | 说明 |
|---|---|---|
| 1 | `id` | `P1`/`P2`…（实例号，文件内唯一） |
| 2 | `type` | 类型码（GM 名称，查总登记表） |
| 3 | `subtype` | 子类型码，可 `-` |
| 4 | `section` | **声部/组**（如 `choir_s`、`strings_1`），可 `-`；`per_section` 按它合并 |
| 5 | `constraints` | **收束覆盖**：`k=v,k=v`（如 `strings=2,max_double_stops=0`），可 `-` |

> 人 = 独立实例（`P#`）；"同一声部的一组人"共用 `section`，合并时按 `section` 归并。
> 无 `section` 时回落到"类型 + 子类型"合并（兼容单钢琴）。

### 3.3 `lyrics` 区块 —— **已移除**

歌词块不再存在（读到时直接拒绝，仅容忍空的 `lyrics 0` 以便读旧文件）。
人声改由事件流里的 **发声段** 承载，见 §3.3d。

### 3.3b `curves` 区块（5 列，可选）

```
curves 2
1 0 0 300 0
1 0 1000000 900 1
```

| # | 字段 | 说明 |
|---|---|---|
| 1 | `instrument_id` | 乐器实例号 |
| 2 | `param` | 字典索引：`dynamics` / `brightness` / `pitch_cents` / `vibrato` / `bow_position` |
| 3 | `time_us` | 绝对时间（微秒） |
| 4 | `value` | 值：dynamics/brightness/vibrato/bow_position 0..1000；pitch_cents −2400..2400 |
| 5 | `ramp` | `0`=阶跃（起点/转折点）· `1`=从上一个点**渐进**到本值 |

- **MS 只存点**；点之间怎么插值由渲染层决定（渐强/渐弱=两个点之间 ramp=1）。
- 同一 `(instrument, param)` 的点必须**按时间严格递增**，首点 `ramp=0`（校验 V15）。
- 区块为空时**整块不写**（旧文件无需迁移）。

### 3.3c `turns` 区块（3 列，可选）

```
turns 1
L00000042 1 800
```

| # | 字段 | 说明 |
|---|---|---|
| 1 | `event_id` | 转折挂在哪个事件上（该音的音头方式） |
| 2 | `kind` | 字典索引：`retrigger` / `bow_change` / `breath` / `restrike` / `mallet` |
| 3 | `strength` | 音头强度 0..1000（1000=正常重音，0=几乎无痕） |

- 转折是**演奏事实**：同键再击、换弓、换气、重复拨弦、换槌——都有各自的声音。
- 它同时是**可演奏性复位**：有显式转折时，C7/C8 不再重复报警。
- 校验 V16：事件必须存在；`kind` 必须是 `dict turn` 里声明过的值；强度 0..1000；
  **动作只给会做它的机制**（如弓向/拨拉只给弓弦、换槌只给击体，表在 `ms_instruments.ACTION_MECHS`）。
- 区块为空时**整块不写**。

> 演奏动作（弓向、拨/拉、泛音、槌硬度、吸气、机械声、弱音器开关）**都用 `turns` 表达**，
> 不需要新增列或区块；取值与适用机制见 `乐器字典.md` §3g。

### 3.3d 发声段（事件流里的 11 列行，第 2 列固定 `vocal`）

演唱结构按**事件 + 段**记：一个事件 = 一个音，音下的**段**各是一个声母或一个韵母，
**段自带起止时间**（写谱侧按发音规则切好，收束层直接读）。

```
events 3
L00000003 3 1000000 2000000 67 - 0 0 1 - 0 4 0 4 - -
L00000003 vocal 0 initial ch B00001 2 0 zh 1000000 1131386
L00000003 vocal 1 nucleus a B00001 2 0 zh 1131386 1897809
L00000003 vocal 2 coda ng B00001 2 0 zh 1897809 1999998
```

| # | 字段 | 说明 |
|---|---|---|
| 1 | `event_id` | 段属于哪个音（必须存在） |
| 2 | `vocal` | 固定标记（区分同流的音符/踏板行） |
| 3 | `index` | 段内顺序，从 0 连续（V18） |
| 4 | `kind` | `initial`（声母）/ `medial`（介音）/ `nucleus`（主元音）/ `coda`（韵尾） |
| 5 | `text` | 段本身：`ch` / `a` / `ng` |
| 6 | `binding` | 绑定号 `B`+5 位：同一个字（或多个音共用的发音结构）共享 |
| 7 | `tone` | 段级声调 0..5（可不同于其它段） |
| 8 | `turn` | `1` = 这个音前重新起音（收束层据此判"重起"） |
| 9 | `lang` | `zh`/`en`/`fr`/`ja`/`ru`/`-` |
| 10 | `start_us` | 段起（微秒） |
| 11 | `end_us` | 段止（微秒） |

> 旧文件里的独立 `vocal` 区块（8/7 列段行）仍能读，写回时并入事件流；
> 更早的 9 列"逐字发声行"已移除。

### 3.4 `retired` 区块

```
retired <n>
L00000005
L00000009
```

### 3.5 `gaps` 区块（3 列，第 3 列到行尾）

```
gaps <n>
<code> <severity> <detail…>
```

- `severity` ∈ `info` / `warn` / `error`
- `detail` 为**行尾自由文本**（可含空格；不含换行）

## 4. 读写规则

1. **写出**：区块顺序固定（头 → instruments → dict → **events（音符 + 踏板 + 发声段，按时间）** → curves → turns → retired → gaps）；同一份数据两次写出**字节一致**。
2. **读入**：必须按区块名分派；未知区块 / 未知 `dict` 名 / 列数不符 → **拒绝**。`events` 里按列数区分：15（或旧 16）= 音符，7/8 = 踏板，11 且第 2 列 `vocal` = 发声段，3–5 且第 2 列 `off` = 止音。旧文件的独立 `pedals` / `vocal` 区块仍可读，重写时并入 `events`；`lyrics` 区块已移除（只容忍空的 `lyrics 0`）。
3. **计数校验**：`events N` 后必须恰好 N 行；其余区块同。
4. **id 校验**：音符 `L`+8 位、踏板 `D`+8 位；同类内全局唯一、与 `retired` 不相交。
5. **字典校验**：索引必须在表范围内；`dict` 表必须在使用前定义。
6. **流式**：`iter_events(path)` 逐行产出，不整份进内存。

## 5. id 规则

- 音符 `L` + **8 位零填充**；踏板控制事件 `D` + 8 位；发声段沿用所属音的 `L` id
- **只增、不复用、允许空洞**
- 删除事件 → id 进 `retired`；新增事件取**当前最大值 +1**
- 定宽保证字典序 = 数字序（排序稳定）

容量：99,999,999 个 id。按 4 小时作品 14.4 万事件、重度改动 20 倍 ≈ 288 万，余量充足。

## 来源：文件尾标识约定


> **口径**：**MS 是数学模型**（事件模型 + 语义 + 六条不变量），它没有文件形态。
> 模型落到磁盘上，只有两种文件尾标识：**`.md`（文档写法）**、**`.py`（脚本写法）**。
> 说「MS 格式」时，指的是**模型**；说文件时，永远说 `.md` 或 `.py`。
> 本页只定**标识与识别规则**，不定义文件内部结构（内部结构见 `MD文档格式.md`）。

---

## 1 两种标识

| 标识 | 是什么 | 谁写 | 产物 |
|---|---|---|---|
| **`.md`** | 模型的**文档写法**：标签式（按拍写音符）或表格式（全字段无损） | 人 / AI | 就是它自己 |
| **`.py`** | 模型的**脚本写法**：调 `ms.Writer` / `ms.start`，可循环可计算 | 人 / AI | 跑完落 `.md` |

两者产物同构：脚本生成的 `.md` 人可以直接接着改，人写的 `.md` 脚本可以继续加工。
选择判据见 `写作入口.md`。

全部小写，单段后缀（`xxx.md`、`xxx.py`）。

---

## 2 分析层：`.s02`

`.s02` 是**分析层**的流式结构（结构测量、动机、分段、句读），由 `.md` 投影而来。
它是**计算产物**，不是写作格式——不要直接写它，也不要把它当成交付物。

---

## 3 四层与各自的落盘

| 层 | 对象 | 落盘 |
|---|---|---|
| 模型层 | `MSDocument`（事件模型） | **不落盘**，内存结构 |
| 写法层 | 文档 / 脚本 | `.md` / `.py` |
| 分析层 | S02 | `.s02`（投影产物，可重算） |
| 呈现层 | 五线谱 / 简谱 / MIDI / 音频 | `.svg` `.png` `.mid` `.wav`（**产物，不是源**） |

> **判据**：能重算出来的东西（谱面、音频、S02 索引）都是产物，不进版本库、不当源文件。

---

## 4 五条规则

**R1 · 文件尾不做版本**
版本写在文件内（schema 字段），不进文件名。升级格式不该导致文件名全线改名。

**R2 · 不得用裸 `.json` 存模型**
裸 JSON 无法表明「这是哪种模型」，读取方只能猜——而猜错等于**静默转换**。

**R3 · 不得互读**
`.md` 不得被当作 `.s02` 读，反之亦然。若允许自动识别，等于把一次**未声明的转换**藏进 IO 层。

**R4 · 标识只表示「属于哪种对象」，不表示「是否合法」**
合法性由内容校验（§7.7 不变量 + 约束档）判定。后缀是 `.md` 不等于内容没问题。

**R5 · 旧档案转换后直接是新标识**

---


MS 事件级已含影响发声的全部因素（信息上等价于五线谱甚至更高）；五线两行、符头、小节线都是**外在形式**；**读谱是渲染器的事**。

| 对象 | 归谁 | 说明 |
|---|---|---|
| **MS 数据** | 模型 | 只存事实；不含任何呈现信息（颜色/布局/谱表/小节线） |
| **呈现样式** | 渲染器 | 渲染器自选；模型不为它留字段 |
| **声音** | 渲染器 | 需 `calibration_ref` 标定 |
| **S02** | 分析层 | 只服务结构计算 |

### 三条边界

**B1 · 渲染器不属模型**：不参与校验、不产生事实。删掉渲染器，模型应完全不受影响。

**B2 · 不得因「不好显示」而改模型**：显示困难不是修改结构的理由。

**B3 · 渲染器可读写，但写入必须经模型校验**：默认只读；一旦提供编辑，必须同时提供校验（见 `RENDERER_AND_EDITOR_SCOPE.md` 的 E1/E2）。

## 6 转换方向（信息差是方向性的）

| 方向 | 怎么处理 |
|---|---|
| 谱面 / MIDI → 模型 | 谱面没有的（力度精确值、释放时刻、踏板深度）按默认值补，但**必须标注来源**（`NOT_PROVIDED`），默认值不得掩盖缺省 |
| 模型 → 谱面 | 谱面没有「力度数值」这类概念，**不写即可，不算丢失** |
| 模型 → S02 | 投影，可重算 |
| 模型 → MIDI / 音频 | 呈现产物 |
