# 演奏与记谱


---

## 来源：记谱与演奏


> 装饰音：MS 里必须写**完整音符**（哪怕原本写成装饰音），因为发声就是要多几个音。

---

## 1. 方向：单向可写，反向只是提示

```
写谱层：  人选「staccato」 ──[奏法参数表]──> 时长 ×0.5 ──┐
                                                       ├─> MS：真实时长 + 真实力度
写谱层：  人选「mf」        ──[力度等级表]──> 1250‰ ────┘

呈现层：  时长 200ms ──[反查]──> "看起来像 staccato"（**提示，不是还原**）
```

**关键**：正向（记号→数值）是**明确的换算**；反向（数值→记号）**多对一，不可逆**。
所以呈现层回显记号时只能说"可能是什么"，**不得声称还原了原谱记号**。

---

## 2. 三张表都在写谱层（不进 MS、不进契约）

| 表 | 作用 | 版本 | 现状 |
|---|---|---|---|
| `dyn-levels-v1` | 力度等级 → 千分比 | v1 | ✅ 已实现 |
| `articulation-v1` | 奏法 → 时长系数 / 力度修正 | v1 | ❌ 未实现 |
| `ornament-v1` | 装饰音 → 展开成哪些音 | v1 | ❌ 未实现 |


### 2.1 `articulation-v1`（**已按开源实现取值**，2026-10-19）

| 奏法 | 时长系数 | 力度修正 | 数据来源 |
|---|---|---|---|
| `staccato` | **0.50** | 1.00 | MuseScore `instruments.xml`：`gateTime 50 / velocity 100` |
| `staccatissimo` | **0.33** | 1.00 | 同上：`gateTime 33`（原草案 0.25 → 改为 **0.33**） |
| `tenuto` | **1.00** | 1.00 | 同上：`gateTime 100` |
| `marcato` | **0.67** | **1.20** | 同上：`gateTime 67 / velocity 120`（原草案 0.7 → 改为 **0.67**） |
| `accent` | — | **1.20** | ⚠ 未在 `instruments.xml` 中找到独立定义；参照 marcato 的力度修正，标为**约定** |

**取值范围说明（来自实现）**：`gateTime` 是**占记谱时长的百分比**，`velocity` 是**相对基准的百分比**（100 = 不改变）。
→ 这印证了我们"时长系数 + 力度修正"的两参数模型是**行业通行的实现方式**，不是自造。

**出处**：[MuseScore 仓库 `share/instruments/instruments.xml`（main 分支）](https://raw.githubusercontent.com/musescore/MuseScore/main/share/instruments/instruments.xml)，
节选（原样）：

```xml
<Articulation name="staccatissimo"> <velocity>100</velocity> <gateTime>33</gateTime> </Articulation>
<Articulation name="staccato">      <velocity>100</velocity> <gateTime>50</gateTime> </Articulation>
<Articulation name="tenuto">        <velocity>100</velocity> <gateTime>100</gateTime> </Articulation>
<Articulation name="marcato">       <velocity>120</velocity> <gateTime>67</gateTime> </Articulation>
```

> 这两列正是**书写侧默认值**：它们描述"人写了这个记号，默认按多少比例发声"，与我们"记号只在写谱层换算"的分层完全一致。

### 2.2 `ornament-v1`（**已按实证研究取值**，2026-10-19）

| 装饰音 | 落点 | 时长 | 依据 |
|---|---|---|---|
| **短倚音**（acciaccatura） | **拍前**（从**前音**借时间） | ≤ 主音 **1/3**，默认 **0.25×主音** | 实证：`previous stolen proportion = 1`（整个装饰音时长取自前音）；文献：short appoggiatura ≤ 1/3 主音 |
| **长倚音**（appoggiatura） | **拍上**（从**主音**借时间） | 主音 **1/2**（范围 1/2–2/3） | 文献：long appoggiatura 取主音一半或三分之二；实证中 main stolen proportion > 0 |
| **颤音**（trill） | 主音与上邻音交替 | **10 次/秒**（实测均值），合理区间 **6.4–12.1 Hz** | 实测：钢琴颤音均值 **10.1 note/s**，右手比左手快约 2 note/s |
| **波音**（mordent） | 主-上邻-主 | 辅助音各占主音 10% | ⚠ 未取得实证，**约定** |
| **回音**（turn） | 上-主-下-主 | 四音各占 15% | ⚠ 未取得实证，**约定** |

**实证来源（已解析正文）**：

1. 《Timing of Ornaments in the Theme from Beethoven's *Paisiello* Variations: Empirical Data and a Model》
   - 三类装饰音实现：**pre-note（拍前，取自前音）/ on-note（拍上，取自主音）/ insertion（插入，不取时）**
   - 实测：Grace 1 与 Grace 3 的 `previous stolen proportion = 1`（即**完全拍前、从前音借时**）；Grace 2 介于两者之间
   - 文献口径：短倚音 **< 1/3 主音**；长倚音 **1/2 ~ 2/3 主音**
   - 另：短倚音更倾向**绝对时长固定**，长倚音**随语境按比例缩放**
2. 《Performance of Piano Trills》（NordicSMC 2019）
   - 钢琴颤音均值 **10.1 note/s**（右手比左手高约 2 note/s）
   - 早期文献：慢 2.0–6.9 Hz、快 7.5–12.4 Hz；按速度分档均值 6.4 / 9.3 / 12.1 Hz

**邻音取音必须在上游完成**：邻音按调号取调内音，而 MS 不含调号 → 展开只能在谱面/导入层做。

## 3. 装饰音：必须展开成完整音符

| 问题 | 回答 |
|---|---|
| MS 里存装饰音记号吗？ | **不存** |
| 那存什么？ | **展开后的每一个音**：各自的 `onset_us` / `release_us` / `dynamics` / 音高 |
| 谁负责展开？ | 写谱层/导入层，用 `ornament-v1` |
| 展开后能还原"这原本是装饰音"吗？ | **不能**——这是**有损方向**，必须进损失清单 |

**为什么必须展开**：发声就是会多出这些音。若只存一个音加一个"装饰音"标记，计算结果就少音——那才是真的丢信息。

---

## 4. 由此产生的有损方向（必须登记）

| 方向 | 丢什么 | 处理 |
|---|---|---|
| 谱面 → MS | "这里原本是装饰音/断奏/mf" | 展开/换算后**记号消失**，记入损失清单 |
| MS → 谱面 | 无法还原原记号 | 呈现层可**提示**最可能的记号，但须标"推测" |
| MS ↔ MS | 无损失（存的就是结果） | — |

> 这正是"MS 是演奏事实，不是记谱原文"的直接后果。

## 来源：记谱对照


> 目的：MS 存的是**怎么奏**，谱面存的是**怎么读**。两边靠一张对照表互转，避免"各写各的"。
> 实现：`render/ms_notation_map.py`（双向表）+ `render/ms_render_staff2.py`（画出来）。
> 测试：`tests/notation_map_test.py`。

## 1. 总原则

1. **MS 是唯一事实来源**：先有动作（`turns` / `curves` / `pedals`），谱面符号是它的**投影**。
2. **符号可以有多种写法，动作只有一个**：`V`/`∨` 都是上弓 → 都映到 `bow_up`。
3. **有的动作不落符号**：`liaison` / `break` 靠**连线**表达；`key_noise` 这类机械声不记。
4. **反向识别是"推定"**：从谱面回 MS 时，符号明确对应动作；连线则按第 3 节规则**推**。

## 3. 连音 / 延音的**结构性规则**

这两种在 MS 里**不是一个字段**，而是由相邻关系推出来的：

| 情形 | 谱面 | 判定 |
|---|---|---|
| 同一音高 + 前后相接（后音起点 = 前音终点） | **延音线 tie** | 一定是"一个音被分成两半" |
| 不同音高 + 相接 + 后音标了 `liaison` | **连音线 slur** | 作者明确要连 |
| 不同音高 + 相接 + 没标 | **不画** | 谱面连音线是**有意标**的，不能自动加 |
| 有空隙 | 不画 | 断奏/分句 |
| 后音带 `restrike` / `retrigger` / `bow_change` / `break` | 不画 | 那是**重新发音**，不是连 |

> 所以「连音」在 MS 里 = 相邻音不留缝 + （可选）`liaison`；
> 「长音」在 MS 里 = 一个事件 + `off` 推后（或拆成多个相接事件画 tie）。

## 5. 互换流程

```
MS  ──(ms_notation_map.symbol_for / arcs_for)──►  谱面（SVG）
谱面 ──(by_symbol / 相邻关系规则)──────────────►  MS（turns + 相邻时间）
```

注意：
- **不写符号 ≠ 没有动作**：没有 `turns` 的音就是"普通奏法"。
- **画了符号必须能从 MS 反推**：所以对照表是双向的，`tests/notation_map_test.py` 会检查覆盖。
- 谱面层仍不做的：跨行连线、符尾斜度、装饰音记号回显（见 `已知边界.md`）。

## 来源：参数语义


> 目的：让"渲染器只读 `.ms` 就能渲染"成立——**每个参数都必须有明确的音频语义**。
> 没有语义的参数，渲染器只能忽略，等于"写了没用"；要么补语义，要么明确标注"不进声音"。
> 状态用语：**已定义** / **部分** / **未定义** / **不进声音**。

## 1. 事件（`events[].`）

| 字段 | 含义 | 音频行为 | 状态 |
|---|---|---|---|
| `id` | 稳定标识 | 不参与发声；编辑/引用用 | 不进声音 |
| `instrument_id` | 第几号乐器/人 | 选采样组、通道、声像 | 已定义 |
| `onset_us` | 起始（µs） | 采样触发时刻；**精确到微秒，不量化** | 已定义 |
| `pitch.semitone` | 键号 | 采样键位（含音域内插值） | 已定义 |
| `pitch.step/alter/octave` | 拼写 | 不参与发声（只影响记谱/渲染） | 不进声音 |
| `release_us` | 松开时刻 | 进入释放段（衰减起点） | 已定义 |
| `release_state` | `given`/`sustaining`/`NOT_PROVIDED` | `given`→按 `release_us` 松；`sustaining`→持续到踏板或曲终；`NOT_PROVIDED`→自然衰减 | **部分**（sustaining 只做延长，未定义"曲终强制收尾"的听感） |
| `dynamics.permille` | 力度（0–1000） | 增益 + 亮度（高次泛音比例） | 已定义 |
| `dynamics.state` | 五态 | `VALUE`→用 permille；`NOT_PROVIDED`→锚点默认；其余→默认 + 标注 | 已定义 |
| `dynamics.scale` | 力度标尺 | 决定 permille→声音的曲线（`relative_permille`/`velocity_steps`/`continuous`…） | **部分**（只有一种曲线实现） |
| `dynamics.calibration_ref` | 标定来源 | 不参与发声（溯源标注） | 不进声音 |
| `dynamics.src` | 数值来源 | 不参与发声 | 不进声音 |
| `is_grace` | 装饰音 | 极短起音、不单独占时值；力度按同组处理 | **未定义**（建议：独立短包络，力度衰减 20%） |
| `excitation_type` | `impulse`/`sustained` | `impulse`→击弦式指数衰减；`sustained`→持续激励，松手才衰减 | **未定义**（当前都按 impulse） |

## 6. 七项语义定义（v1 定稿，2026-10-21）

> 每条给出**可实现的判定**，不是口号。标"已实现"的进 `make_audio`；标"已定义·待实现"的只定语义。

### 6.1 `excitation_type`（激励类型）

| 值 | 包络 | 判定 |
|---|---|---|
| `impulse` | 起音后**指数衰减**，半衰期由音高与力度决定 | 钢琴/拨弦/打击 |
| `sustained` | 起音后**保持幅度**，直到 `release_us` 才进入衰减（衰减 120 ms） | 弓弦/管乐/人声 |

- `sustained` 且 `release_us is None`：保持到曲终，末尾 300 ms 淡出
- 缺省 `impulse`
- **状态：已定义 · 已实现**（原生合成）

### 6.2 `is_grace`（装饰音）

- 时长：`min(release_us − onset_us, 90 ms)`（无 release 时按 90 ms）
- 力度：`permille × 0.8`（不额外标注来源）
- 不参与踏板延音（装饰音不延）
- **状态：已定义 · 已实现**

### 6.3 `PedalSegment.kind`（踏板种类）

| 值 | 作用 | 实现判定 |
|---|---|---|
| `sustain` | 延音（制音器全抬） | 现有逻辑 |
| `sostenuto` | 只保持**踩下瞬间已按下的音**（`targets` 列出） | 只对这些 id 延长，其余不延长 |
| `una_corda` | 弱音：频谱暗化 + 音量 −3 dB | 高次泛音幅度 ×0.45，总增益 ×0.71 |

- `targets` 为空且 `scope="mechanical"`：`sostenuto` 退化为不作用（记 gap 由生成层负责）
- **状态：已定义 · 部分实现**（`sustain` 实现；`sostenuto`/`una_corda` 待实现）

### 6.4 `PedalSegment.scope / targets`

| scope | 含义 |
|---|---|
| `mechanical` | 机械作用：对该乐器所有正在响的音生效 |
| `explicit` | 只对 `targets` 列出的音生效（`("global",)` 表示全部） |

- `targets` 里不存在的 id → 由 V10 拒绝（已实现）
- **状态：已定义 · 部分实现**（sustain 走 mechanical；explicit 待实现）

### 6.5 `subtype`（乐器子类型）

- 语义：**选择采样组**（同一 type 下的不同音色）
- 原生渲染器：按 `subtype` 选采样集；缺省用 type 默认
- MIDI 通路：映射到不同 GM program（已有 `SUBTYPES[].program`）
- **状态：已定义 · 待实现**（需要采样库）

### 6.6 `dynamics.scale`（力度标尺）

| 值 | 曲线 | 判定 |
|---|---|---|
| `relative_permille` | `amp = (permille/1000)^1.1` | 相对强度，默认 |
| `velocity_steps` | 分级：把 permille 映到 pp..ff 若干档，取档位值 | 钢琴式离散力度 |
| `continuous` | `amp = permille/1000`（线性） | 弓弦/管乐连续 |
| `fixed_levels` | 只用锚点（等同 `VALUE` 但不可变） | 打击乐 |

- **状态：已定义 · 已实现**（三种曲线）

### 6.7 `section`（声部组）

- 语义：混音分组。**同 section 的实例共享增益与声像**。
- 默认：增益 1.0、声像居中；可由渲染器按组配置（如弦乐组略靠左）
- 不影响 MIDI 导出（MIDI 只按 `channels` 策略合并）
- **状态：已定义 · 待实现**（需要混音层）

## 7. 三条判定规则

1. **能定义就定义**：参数写进 MS 就必须能被声音消费；否则应移出 MS。
2. **"不进声音"要显式**：溯源/记账字段（`src`/`calibration_ref`/`gaps`）允许不发声，但必须在表里标清。
3. **MIDI 通路的损失要可预期**：本表每个"部分/未定义"项，就是 MIDI 路径会丢或渲染层会猜的地方。

## 2. 影响什么

| 听觉维度 | 主要因子 |
|---|---|
| **音量** | 力度 · 组增益 · 踏板（una_corda −3 dB）· 混响量 |
| **音色/亮度** | 力度 · 族/子类型 · una_corda（高次泛音 ×0.55）· EQ |
| **时长** | 释放时刻 · 踏板（sustain/sostenuto）· 激励类型 · 装饰音截断 |
| **音高** | 键号（微弯仅人声声调用） |
| **空间** | section 声像 · 混响 |

## 3. 乘因在哪一层

**结论：乘因在渲染层，不在 MS。**

| 数据 | 谁负责 |
|---|---|
| 因子的**值** | MS 记录（事实） |
| 因子的**语义** | `PARAM_SEMANTICS`（定义每个因子怎么解释） |
| 因子的**组合（乘因）** | **渲染器**（`audio/make_audio.py` 或原生采样器） |

理由：

1. 同一份 MS 可以用不同渲染器（合成 / 采样 / 未来权重），组合方式不同；
2. 乘因涉及大量工程细节（包络相乘、频谱混合、动态压缩），不属于"事实"；
3. MS 若记录乘因结果，就等于把某一种渲染器的实现写死进数据。

**示例（当前合成器）**：

```
振幅 ≈ amp(permille, scale) × 组增益(section) × 踏板衰减(una_corda) × 0.16
亮度 ≈ 族基础亮度 + 力度驱动 − una_corda 压暗
时长 ≈ 释放时刻 ⊕ 踏板延音 ⊕ 激励类型（sustain 保持）− 装饰音截断
```

`⊕` 表示"按规则合并"，具体规则在渲染器实现里，**MS 只给输入**。

## 1. 为什么单独一层

| 层 | 存什么 | 算什么 |
|---|---|---|
| **MS** | 字（text）、**词典声调**（tone）、语言（lang）、音节序（syllable_index） | — |
| **本层** | — | **表面声调**（变调后）、连读、段时长、气声/吸气位置 |
| 渲染器 | — | 只读 `VocalPlan`，不碰拼音规则 |

**核心分离**：MS 记「词典里这个字读几声」，本层算「在这个词里实际唱成几声」。

例：

```
MS:      你好  nǐ(3) hǎo(3)
VocalPlan: ní(2) hǎo(3)      ← 三声连读变调（词内）
```

## 2. 拼音规范化（进入计算前先做）

| 规则 | 例 |
|---|---|
| `yi → i`、`ya → ia`、`ye → ie`、`you → iou` | yi 服 → i fu |
| `wu → u`、`wa → ua`、`wo → uo` | wu → u |
| `yu → ü`、`yue → üe`、`yuan → üan`、`yun → ün` | yu → ü |
| `j/q/x + u → ü` | ju → jü、qu → qü、xu → xü |
| `v` 视为 `ü`（输入法写法） | lv → lü |
| 零声母 | `a/o/e/ai/ei/ao/ou/an/en/ang/eng/er` 无声母 |

规范化后，一个音节 = `[声母] + 韵母`，韵母 = `[介音] + 主元音 + [韵尾]`。

## 3. 段划分与时长模板

```
chang = ch + a + ng
        └声母┘ └主元音┘ └韵尾┘
```

| 段 | 默认占比 | 说明 |
|---|---|---|
| 声母 | 15–25% | 爆破/摩擦；零声母时并入元音起始 |
| 过渡 | 8–12% | 声母→元音的共振峰 locus 过渡 |
| 主元音 | 55–65% | **音符长短主要改这里** |
| 韵尾 | 10–20% | n / ng / r |

**调整规则**：

- 音符长（> 1s）→ 主元音加长，声母/韵尾占比下降。
- 音符短（< 150ms）→ 先压韵尾，再压过渡。
- 一字多音（拖腔）→ **韵母拉长，声母只在第一音出现**。

## 4. 收束规则 V1–V8

| # | 规则 | 判定 | 例 |
|---|---|---|---|
| **V1** | 一字一音：按模板切段 | 音节数与音数 1:1 | 长 → ch/a/ng |
| **V2** | 一音多字：按 `syllable_index` 升序塞入 | 一个音挂多个 Lyric | 一个音唱「花儿」 |
| **V3** | 一字多音（拖腔）：韵母拉长，声母不重复 | 多个音共享 `syllable_id` | 「长——」 |
| **V4** | 三声连读变调 3+3→2+3，**仅词内** | 相邻两音节均 3 声且同词 | 你好 → ní hǎo |
| **V5** | 「一」变调：后接 4 声→yí，否则→yì | 字为「一」 | 一个 yí ge · 一天 yì tiān |
| **V6** | 「不」变调：后接 4 声→bú | 字为「不」 | 不对 bú duì |
| **V7** | 轻声：短、弱、音高依附前字 | tone=5 | 妈妈 mā ma |
| **V8** | 吸气点必须在词/句边界 | `inhale` 标记落在词中 → 违规 | 词中间吸气 → 报 |

**附加约束**：

- 变调只在**同词**内生效；跨词不连读（除非显式标 `liaison`）。
- 歌词缺 `tone`（0=未标）时**不猜**，直接报 `V-tone-missing`，用默认平调。
- 多段歌词（`verse`）分别生成 Plan，互不影响。

## 5. MS 字段增量（可选，向后兼容）

当前歌词行 6 列：`event_id verse syllable_index tone lang text`

新增两个**可选**分组字段，写作 8 列：

```
event_id verse syllable_index tone lang word_id syllable_id text
```

| 字段 | 含义 | 缺省 |
|---|---|---|
| `word_id` | 同一词的音节共享；`-` = 单字成词 | `-` |
| `syllable_id` | 同一音节跨多个音时共享（拖腔）；`-` = 一音一音节 | `-` |

**兼容规则**：

- 解析：歌词行 token 数 ≥ 8 → 按 8 列读；≤ 7 → 按旧 6 列读（`word_id`/`syllable_id` 视为 `-`）。
- 写出：有分组信息才写 8 列；否则写 6 列（**旧文件字节不变**）。
- 校验：
  - `V-L1` 同一 `word_id` 的音节必须连续（中间无休止/别的词）。
  - `V-L2` 同一 `syllable_id` 的音必须连续且同音高（拖腔不许变调）。
  - `V-L3` `syllable_id` 与 `syllable_index` 不冲突。

## 6. VocalPlan 结构

```
VocalPlan
 ├─ rules_version: "vocal-1.0"
 ├─ syllables[]
 │    ├─ char, pinyin, lexical_tone, surface_tone
 │    ├─ word_id, note_ids[]
 │    ├─ segments[]
 │    │     ├─ kind: initial | transition | nucleus | coda | inhale
 │    │     ├─ dur_us
 │    │     ├─ formant_targets: (F1, F2, F3)
 │    │     ├─ noise_amount: 0..1
 │    │     └─ voiced: bool
 │    ├─ breathiness: 0..1
 │    ├─ vibrato: (rate_hz, depth_cents) | None
 │    └─ portamento_us
 └─ issues[]
      ├─ code: V1..V8 / V-L1..V-L3 / V-tone-missing
      ├─ severity: error | warn
      └─ detail, event_ids
```

## 7. 与渲染器的接口

```
notation/pinyin.py    拼音 → 规范化 + 段模板（纯数据/规则）
transform/vocal_plan.py   文档 + 歌词 → VocalPlan + issues（本层）
audio/ms_sing.py      VocalPlan → 波形（共振峰 + 噪声源）
```

`make_audio` 只调 `ms_sing`；规则改动不影响合成器。

## 8. 已知边界

| 项 | 现状 |
|---|---|
| 方言（粤语/闽南语） | 不支持，仅普通话 |
| 多音字 | 按上下文词典选择；未做则报 `V-polyphone` |
| 儿化（r） | 作为韵尾 `/r/` 处理，不做卷舌色彩建模 |
| 语气（疑问/感叹语调） | 不建模（属 S02 语义层） |
| 情感 | 不建模（同上） |

## 9. 未决问题

1. 词边界来源：显式 `word_id` 为主，还是允许自动分词兜底？
2. 拖腔的 `syllable_id` 是否也要记录「第几个音是第几个音节」的顺序？
3. 吸气（`inhale`）是 `turns` 新 kind，还是独立的 `breath` 块？
4. 变调是否要提供「关闭开关」（用于方言或特殊唱法）？
