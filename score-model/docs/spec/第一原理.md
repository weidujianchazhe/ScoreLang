# 第一原理（2026-10-19）

> 用途：当具体做法有争议时，回到这几条判断。**不是规范，是判据**。
> 每条都写明"由此得出什么、以及它禁止什么"。

---

## P1 · 结构允许 ≠ 计算需要 ≠ 写谱许可

**MS 是数学结构，允许合法数值存在；允许之后，它同样可以被计算。**

三层各问一句话：

| 层 | 问的问题 | 例：88 键同一时刻叠加 |
|---|---|---|
| **数学结构** | 允许吗？ | **允许**（可同刻多事件、可同键重复、可多琴） |
| **计算** | 能算吗？ | **能算**（每个事件各自出参数；频率相同、力度可不同） |
| **写谱** | 下笔时收束吗？ | **收束**（一台琴 88 键 + 3 踏板，同键同刻不得重复） |

**关键**：物理上做不到，**不构成计算失败的理由**。计算层不得因为"真实钢琴不可能"而拒绝、合并或报错——那是写谱层的约束，不是计算层的前提。

- 结构层**不因"实际用不到"删字段**
- 计算层**不因"物理不可能"拒算**
- 写谱层**按乐器机构收束**（约束档 `single_piano` / `n_pianos` / `unlimited`）

> 并且——**"同键同刻"在结构上合法**：数学上就是两个事件；只有落到**一架琴**上时，
> "同一个键同一微秒被击两次"才是非法。因此该判据属**演奏收束**，不属 `validate()`。
> 代码对应：`ms_events.validate()` 不再判同键同刻；`ms_events.check_realization()` 判
> `R-1 同键同刻` / `R-2 同键重击`（未释放即再击）/ `R-3 琴号越界` / `R-4 超出 88 键`。

**禁止**：
1. 因为"渲染器不支持"或"人弹不出来"就删字段、砍范围
2. 在计算层以"物理不可行"为由拒绝或静默合并事件
3. 把写谱约束（88 键、三踏板绑定）当成模型不变量

---

## P2 · 计算只吃数值

**渲染/发声只读数值，不读记号、不查等级表、不做语义解释。**

- 计算层的输入是 `dynamics_permille`（数值）、`onset_us`（数值）、`depth_permille`（数值）
- 计算层**不知道** `mf` 是什么，也不需要知道

**禁止**：在计算路径里塞"如果是 mf 就怎么怎么样"这类分支。

---

## P3 · 写谱时才做换算（等级 → 数值）

**`p/mf/f` 这类等级，是"写谱时的表达手段"，不是 MS 的内容，也不是计算输入。**

- 写谱界面提供等级选项；用户选 `mf` → 查**默认等级表** → 得到一个数值 → 写入 MS
- 这个数值的来源标记是 `notated_inferred`（由记谱等级推断）
- 人若直接给数值（例如把滑块拉到 1500‰），那是 `authored`
- 什么都没写 → `NOT_PROVIDED`

```
写谱层：  等级(mf) ──[默认等级表]──> 数值(1250)
                                    │
MS：                              数值 + 来源标记
                                    │
计算层：                            数值 ──> 声音参数
```

**禁止**：把等级表塞进 MS 语义；让计算层依赖等级；把"等级"当成"事实"。

---

## P4 · 缺失必须有痕

未提供 ≠ 中性。存储层记 `NOT_PROVIDED`，计算层可按中性处理，但**该处理必须可见**。

**禁止**：用默认值填空并让它看起来像源数据。

---

## P5 · 契约/模型/引擎三层各管一段

| 层 | 管什么 | 不管什么 |
|---|---|---|
| 契约 | 转换义务、覆盖清单、比较维度 | 具体数值、渲染样式 |
| 模型（MS） | 事实的结构与不变量 | 换算表、呈现、声音 |
| 引擎 | 读写、呈现、编辑、参数计算 | 定义事实、改模型 |

**禁止**：让工具反推模型（"不好显示就改结构"）、让实现自定契约（"做不到就排除"）。

---

## 由 P1–P5 直接得出的两个结论

1. **力度等级表属写谱层**（P3），是"默认的、可替换的"约定，**不参与比较与计算**
2. **MS 不猜记号**（P3）：没有明确数值就不写数值，标 `NOT_PROVIDED`；要换算必须经过显式等级表
